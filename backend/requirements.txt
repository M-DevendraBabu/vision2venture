# Upper bounds on the libraries the trained models are pickled against.
#
# The models in app/ml_models were fitted with scikit-learn 1.9.0. A joblib pickle
# stores the estimator's internal attributes, not a portable description of it, so
# loading one under a different version means scikit-learn reconstructs an object
# its own code may no longer agree with. It warns about this on every boot:
#
#   InconsistentVersionWarning: Trying to unpickle estimator GradientBoostingClassifier
#   from version 1.9.0 when using version 1.9.1 ... might lead to ... invalid results
#
# Across a patch release that is almost always harmless. The real exposure was the
# open floor: scikit-learn>=1.3.0 resolves to whatever is newest when the image is
# built, so the day 1.10 or 2.0 ships, a deploy that changed nothing would load
# these models under code they were never fitted with - and the failure mode is not
# necessarily a crash, it is quietly different predictions.
#
# Bounded to the minor series the models were trained on. Retrain and raise these
# together, never one without the other.
scikit-learn>=1.9,<1.10
joblib>=1.3,<2
pandas>=2.0,<4
numpy>=2.4,<3
groq>=0.4.0
requests>=2.31.0
beautifulsoup4>=4.12.0
pytrends>=4.9.0
